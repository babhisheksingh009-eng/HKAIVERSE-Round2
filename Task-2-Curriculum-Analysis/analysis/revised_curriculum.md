# Proposed Revised CSE Curriculum

## 1. Objective

This proposal recommends practical curriculum improvements to strengthen programming, software engineering, data analysis, cloud computing, and artificial intelligence skills.

These recommendations are proposals for academic review. They do not represent an official change to the IFHE curriculum.

## 2. Principles for Revision

- Preserve essential computer science foundations.
- Improve practical assignments and laboratory work.
- Avoid unnecessary duplication between subjects.
- Introduce industry-relevant projects.
- Respect prerequisites and applicable university regulations.
- Confirm all semester and credit values against the official syllabus before implementation.

## 4. Proposed New Learning Modules

The following are proposed modules, not confirmed additions to the official programme.

### Module A: Generative AI and LLM Applications

Topics:
- Large language model fundamentals
- Prompt design and output evaluation
- Retrieval-augmented generation concepts
- Responsible AI and privacy
- Building and testing a small AI application

### Module B: Software Testing and Deployment

Topics:
- Unit and integration testing
- Git collaboration and code review
- API testing
- Docker fundamentals
- Application deployment and basic monitoring

These modules could be introduced as approved elective content, integrated into existing courses, or delivered through a capstone, depending on university regulations.

## 5. Proposed Practical Capstone

**Title:** AI-Assisted Curriculum Analysis and Improvement System

The proposed system would allow a reviewer to:
1. Load a structured curriculum dataset.
2. Search and filter courses.
3. Compare course topics with documented job-description requirements.
4. Identify possible skill gaps.
5. Display proposed course-level improvements.
6. Export a report for human review.

AI-generated recommendations would require verification. The system would support academic decision-making rather than automatically changing an official curriculum.

## 6. Credit-Change Calculation

The assignment requires proposed changes affecting approximately 20–25% of programme credits while keeping the overall credit total balanced.

The official programme credit total and applicable regulations must be confirmed before this calculation can be finalised.

Use the following calculation:

**Programme credits affected (%) = Credits affected by proposed changes ÷ Total programme credits × 100**

For example, if a verified programme contains 160 credits, a 20–25% range would equal 32–40 credits.

This is an illustration only. It is not a claim that the official programme contains 160 credits.

Before finalising the calculation:
1. Obtain the official curriculum applicable to the student's admission batch.
2. Confirm the total credits required for graduation.
3. Identify the credits affected by each proposed change.
4. Check prerequisites and semester restrictions.
5. Confirm that the revised credit total remains balanced and complies with university regulations.

## 7. Prerequisites and Regulatory Conditions

- Foundational programming should precede advanced programming projects.
- Data Structures and Algorithms should support advanced software and AI coursework.
- Database and programming knowledge should precede database-backed application projects.
- Mathematics, statistics, and programming foundations should support machine learning.
- Deep learning and NLP should build on appropriate foundational knowledge.
- New modules require approval under the applicable university regulations.
- No course should be removed or have its credits changed without reviewing official requirements.

## 8. Limitations

- The official syllabus and regulations for the applicable admission batch must be checked.
- Proposed course recommendations are not official university decisions.
- Industry skill-gap findings are based on a limited sample of job descriptions.
- The credit-impact calculation remains provisional until official credit totals and proposed changes are verified.
- Faculty or graduate feedback should be documented only if it is actually obtained.

## 9. Conclusion

This proposal retains essential CSE foundations while recommending more practical work in software testing, cloud deployment, data-driven development, and AI applications.

The proposal should be reviewed against the official syllabus, credit requirements, prerequisite structure, and relevant industry evidence before implementation.

Retain Data Structures and Algorithms and its core problem-solving outcomes. Confirm the course content and credits against the official curriculum for the 2023 admission batch.

### UPDATE
Update DBMS practical work to include secure SQL queries, database design exercises, and testing. First compare these proposals with the existing syllabus and laboratory exercises.

### REDUCE — provisional review
Review introductory programming topics across C, Java, and Python for possible duplication. Reduce content only if a comparison of the official syllabi confirms unnecessary repetition; do not remove essential programming outcomes.

### ADD — provisional proposal
Consider a practical API integration and deployment learning module. Check whether equivalent content already exists in Web-Enabled Technologies, Cloud Computing, or another course before proposing a new module.

### Evidence and credit-balance condition
These are proposals, not verified findings. Support decisions with the applicable official syllabus, dated job descriptions, and documented comparisons.
